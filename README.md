# יומן מסחר — אפליקציית ניהול פוזיציות וסטטיסטיקה

אפליקציית ווב אישית לניהול מסחר בשוק ההון, המקושרת ל-Google Sheet אחד בדרייב שהוא מקור האמת היחיד. כוללת מחשבון גודל פוזיציה, יומן ניהול פוזיציות מלא (כניסה/חיזוק/מכירה חלקית/סגירה), וטאב סטטיסטיקה חי.

## מחסנית טכנולוגית

React + TypeScript + Vite, Tailwind CSS v4, ללא שרת — הבקאנד הוא Google Apps Script Web App.

---

## שלב 1: יצירת Google Sheet

1. היכנס ל-[Google Drive](https://drive.google.com) שלך וצור **Google Sheet** חדש (לדוגמה: "יומן מסחר").
2. השאר אותו ריק — הקוד ייצור אוטומטית את הלשוניות `פוזיציות`, `פעולות` ו-`סטטיסטיקה` בפעם הראשונה שיישלח אליו בקשה.

## שלב 2: הדבקת קוד ה-Apps Script

1. בתוך הגיליון: **תוספים ← Apps Script** (Extensions ← Apps Script).
2. מחק את כל התוכן שקיים בקובץ `Code.gs` ברירת המחדל.
3. פתח את הקובץ `google-apps-script.gs` מהפרויקט הזה, העתק את כל התוכן, והדבק אותו בעורך.
4. שמור (סמל דיסקט או `Ctrl+S`).

## שלב 3: פריסה כ-Web App

1. בעורך ה-Apps Script, לחץ על **Deploy ← New deployment** (פריסה ← פריסה חדשה).
2. ליד "Select type" לחץ על גלגל השיניים ובחר **Web app**.
3. הגדר:
   - **Execute as:** `Me` (אתה) — כדי שהאפליקציה תכתוב לגיליון בשמך.
   - **Who has access:** `Anyone` (כל אחד) — כדי שהאפליקציה בדפדפן תוכל לגשת ללא התחברות Google.
4. לחץ **Deploy**. בפעם הראשונה תתבקש לאשר הרשאות — אשר את כל השלבים (ייתכן שתראה אזהרת "אפליקציה לא מאומתת"; לחץ Advanced ← Go to [project name] (unsafe) כי זהו הקוד שלך).
5. העתק את **Web app URL** שמופיע (נראה כך: `https://script.google.com/macros/s/AKfycb.../exec`).

> **שים לב:** בכל פעם שאתה עורך את הקוד ב-Apps Script, יש ליצור **פריסה חדשה** (New deployment) או לעדכן פריסה קיימת (Manage deployments ← Edit ← New version) כדי שהשינויים ייכנסו לתוקף בכתובת ה-Web App.

## שלב 3א: קוד גישה והתראות (חובה)

הכתובת של ה-Web App פתוחה לכל מי שמחזיק בה ("Anyone"), ולכן השרת דורש קוד גישה סודי בכל בקשה.

1. צור קוד אקראי ארוך (לפחות 32 תווים), למשל במסוף: `openssl rand -hex 32`.
2. בעורך Apps Script: **Project Settings ← Script Properties ← Add script property**:
   - `APP_TOKEN` = הקוד שיצרת
   - `twelveDataApiKey` = מפתח Twelve Data (אם יש)
   - `REQUIRE_TOKEN` = `true` — רק אחרי שהזנת את הקוד באפליקציה בכל המכשירים. עד אז בקשה בלי קוד
     עדיין מתקבלת (קוד שגוי נדחה תמיד). אם משהו נשבר, משנים ל-`false` — בלי פריסה מחדש.
3. התראות (מחיר יעד ברשימת המעקב, חציית סטופ) רצות מטריגר זמן: בעורך בוחרים בפונקציה
   `installAlertTrigger` ← **Run**, ומאשרים הרשאה. היא רצה כל 15 דקות, ופועלת רק בשעות המסחר בארה"ב.
4. באפליקציה: **הגדרות ← קוד גישה לשרת**, בכל מכשיר.

לעולם לא לשמור את הקוד בקוד המקור או ב-GitHub.

## שלב 4: הגדרת האפליקציה

1. הרץ את האפליקציה מקומית (`npm run dev`) או פתח אותה אחרי פריסה.
2. עבור לטאב **הגדרות**.
3. הדבק את כתובת ה-Web App שהעתקת בשלב 3.
4. לחץ **בדוק חיבור** — אמור להופיע "החיבור תקין".
5. עדכן הון התחלתי, יתרת חשבון ברירת מחדל וסכום סיכון ברירת מחדל לפי הצורך.
6. לחץ **שמור הגדרות**.

הכתובת נשמרת ב-localStorage של הדפדפן, כך שכל מכשיר/דפדפן צריך להגדיר אותה בנפרד.

## פיתוח מקומי

```bash
npm install
npm run dev
```

האפליקציה תיפתח בכתובת שמוצגת בטרמינל (בדרך כלל `http://localhost:5173`).

## בנייה ופריסה ל-GitHub Pages

1. ודא ש-`base` בקובץ [vite.config.ts](vite.config.ts) תואם לשם ה-repository שלך ב-GitHub:
   ```ts
   base: '/שם-הריפו-שלך/',
   ```
2. בנה את הפרויקט:
   ```bash
   npm run build
   ```
   התוצר ייווצר בתיקיית `dist/`.
3. פרסם את `dist/` ל-GitHub Pages. הדרך הפשוטה ביותר:
   ```bash
   npm install -D gh-pages
   npx gh-pages -d dist
   ```
   ואז הפעל ב-Settings ← Pages של ה-repository את המקור `gh-pages` branch.

   לחלופין, השתמש ב-GitHub Actions (workflow סטנדרטי ל-Vite + Pages).
4. לאחר הפריסה, האפליקציה תהיה זמינה בכתובת `https://<username>.github.io/<repo-name>/`.
5. בכל פתיחה ראשונה במכשיר/דפדפן חדש, יש להגדיר מחדש את כתובת ה-Web App בטאב **הגדרות** (הנתונים בגיליון עצמו לא נפגעים — זו רק הגדרה מקומית של הדפדפן).

## מבנה הנתונים בגיליון

### לשונית "פוזיציות"
שורה אחת לכל עסקה, מייצגת את המצב הנוכחי שלה (סטאטוס, כמות נוכחית, רווח/הפסד ממומש וכו').

### לשונית "פעולות"
שורה לכל פעולה בודדת (כניסה / חיזוק / מכירה חלקית / סגירה) — יומן מלא של כל מה שקרה בכל עסקה.

### לשונית "סטטיסטיקה"
נבנית אוטומטית ע"י ה-Apps Script עם נוסחאות חיות (`SUMIF`/`COUNTIF`/`AVERAGEIF`) שמצביעות ללשונית "פוזיציות". מתעדכנת לבד גם אם עורכים את הגיליון ידנית.

---

## פתרון תקלות

- **"החיבור נכשל" בבדיקת חיבור:** ודא שהפריסה היא מסוג Web app עם Access = Anyone, ושהעתקת את הכתובת המלאה (מסתיימת ב-`/exec`, לא ב-`/dev`).
- **שינויים בקוד לא נכנסים לתוקף:** צור **New deployment** או עדכן את הפריסה הקיימת (Manage deployments ← Edit ← Version: New version ← Deploy).
- **הנתונים לא מופיעים אחרי פעולה:** בדוק בקונסולת הדפדפן אם יש שגיאת CORS/רשת; ודא שה-URL בהגדרות תקין ומסתיים ב-`/exec`.
- **לשונית הסטטיסטיקה לא מתעדכנת:** היא נבנית מחדש בכל `doPost` מוצלח (`ensureStatsSheet_`). אם ערכת ידנית את לשוניות "פוזיציות"/"פעולות", בצע פעולה כלשהי מהאפליקציה (או הרץ ידנית את `ensureStatsSheet_()` מעורך ה-Apps Script) כדי לרענן אותה.

## סביבת בדיקה נפרדת (נתונים פיקטיביים בלבד)

לבדיקת שינויים בשרת בלי לגעת ביומנים האמיתיים:

1. צור שני גיליונות Google חדשים עם נתונים פיקטיביים (אחד במקום "אמיתי", אחד במקום "דמו"), עם הלשוניות
   "פוזיציות" ו"פעולות" באותו מבנה.
2. צור את קוד השרת לבדיקה:
   `node scripts/make-test-backend.mjs <מזהה-גיליון-1> <מזהה-גיליון-2> /path/outside/repo/test-backend.gs`
3. ב-[script.google.com](https://script.google.com) צור פרויקט **חדש ועצמאי**, הדבק את הקובץ שנוצר, הגדר בו
   `APP_TOKEN` משלו (לא הקוד האמיתי), ופרוס כ-Web App. זו כתובת נפרדת לגמרי מהשרת האמיתי.
4. הרץ את האפליקציה מקומית מול גיליונות הבדיקה:
   `VITE_TEST_SHEET_ID_REAL=<מזהה-1> VITE_TEST_SHEET_ID_DEMO=<מזהה-2> npm run dev`
   ובהגדרות הזן את כתובת שרת הבדיקה ואת קוד הבדיקה.

הבדיקות האוטומטיות (`npm test`) לא פונות לשום שרת או גיליון — הכול מדומה.
